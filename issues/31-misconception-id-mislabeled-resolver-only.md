# 31 — `misconception.id` (and likely `concept.option.id`) is mislabeled "resolver only"

**What to build:** Correct the `schema` flag for `misconception.id` (and
audit `concept.option.id`, which shares the same type) in
`src/shared/authoring/diagnostics.js`, so the generated
`docs/diagnostics.md`, `/api/v1/diagnostics` and the plugin's
`references/diagnostics.md` say `schema: true`, or narrow the code's
description so the "resolver only" claim is accurate for the sub-condition it
actually names.

Found by ticket 13's contract-attack audit
(`tests/audit/contract-attacks/contract_attacks_test.ts`), run against the
deployed API at `https://learn-joshhale.legoguy32109.deno.net`, the downloaded
validator, and an independent draft 2020-12 validator (ajv), not the
project's code.

## The claim under test

`GET /api/v1/diagnostics` marks `misconception.id` `"schema": false`
("resolver only" in `docs/diagnostics.md`), with the description: "The
misconception ID is missing, repeats another in the Concept, does not match
`^[A-Za-z0-9_-]{1,64}$`, or is a reserved name."

## Why it is false for three of its four conditions

`misconception.id`'s value is `$ref: "#/$defs/localId"` in the served schema,
and `$defs.localId` is:

```json
{
  "type": "string",
  "pattern": "^[A-Za-z0-9_-]{1,64}$",
  "not": { "enum": ["__proto__", "constructor", "prototype"] }
}
```

`id` is also `required` on the `misconception` object. So the schema
independently rejects: a **missing** id (required), a **malformed** id
(pattern), and a **reserved-name** id (`not enum`) — three of the four
conditions the code's own description lists. Only "repeats another id in the
Concept" is genuinely cross-item and resolver-only, because JSON Schema
cannot compare array siblings without a `$data` reference the schema does not
use.

`concept.option.id` (also `resolver only`, also `$ref: localId`, also
`required`) has the identical shape and is likely the same mislabeling;
ticket 13's audit did not need a dedicated isolated fixture to notice it
because the option-id fixtures used to demonstrate this always also produced
an independently schema-catchable code from the resulting key/map/feedback
mismatch. It is named here for whoever picks up this ticket to check
directly, alongside `misconception.id`.

## Reproduction

Fixtures committed at
`tests/audit/contract-attacks/fixtures/reserved-name-misconception-__proto__.json`
(and the `constructor`/`prototype` siblings), generated by
`tests/audit/contract-attacks/generate.ts`.

```bash
curl -sS -X POST https://learn-joshhale.legoguy32109.deno.net/api/v1/lesson-resolutions \
  -H 'content-type: application/json' \
  --data-binary @tests/audit/contract-attacks/fixtures/reserved-name-misconception-__proto__.json
# -> 422, diagnostics include "misconception.id" at .../misconceptions/0/id
```

```js
import { Ajv2020 } from "ajv/2020";
const ajv = new Ajv2020({ strict: true });
const schema = await (await fetch("https://learn-joshhale.legoguy32109.deno.net/api/v1/schemas/lesson/v1")).json();
const validate = ajv.compile(schema);
const document = JSON.parse(await Deno.readTextFile("tests/audit/contract-attacks/fixtures/reserved-name-misconception-__proto__.json"));
console.log(validate(document)); // false — the schema ALSO rejects this document, contradicting "resolver only"
```

The rerunnable test asserts this exact, observed behavior at
`tests/audit/contract-attacks/contract_attacks_test.ts`, in
`KNOWN_SCHEMA_CATALOG_MISMATCHES`. It will fail — the useful way — the day
this ticket is closed and the catalog changes to agree.
